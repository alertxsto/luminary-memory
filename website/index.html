Python 3.11+ · No hosted memory service.

hello, memory
first_memory.py
from luminary_memory import MemoryClient

client = MemoryClient(
    db_path="memory.db", scope={"user_id": "u1"}
)
client.ingest(
    "The deploy target is staging",
    user_id="u1", source="quickstart",
    evidence_quote="The deploy target is staging",
)
result = client.recall("where do we deploy?")
print(result.status, result.provenance)
terminal · bash
# Bind memory to an owner
export LUMINARY_USER_ID=u1

luminary-memory add \
  "The deploy target is staging" \
  --tags deploy --source quickstart

luminary-memory recall \
  "where do we deploy?" --limit 5 --json

# Inspect the store, not just the answer
luminary-memory activity --json

02 / From observation to context

A small loop.
A lasting thread.

Memory should help the next turn, not obscure it. Follow a fact from a deliberate write to a scoped, evidence-aware result.

  1. 01 ↗

    Capture what matters

    Ingest a fact with source, tags, ownership, and optional evidence. Keep the durable signal, not every passing sentence.

    client.ingest(...)
  2. 02 ↗

    Keep it in your store

    SQLite is the default. Inspect stored rows, track provenance, and make conflicts explicit instead of silently replacing facts.

    SQLite / pgvector
  3. 03 ↗

    Recall within bounds

    Scope first. Fuse retrieval signals, check evidence, remove duplicates, and fit useful context inside a token budget.

    client.recall(...)
  4. 04 ↻

    Keep memory useful

    Export a backup. Run lifecycle cleanup, consolidation, and pruning. Inspect health as your memory store grows.

    luminary-memory lifecycle
✳

The core retrieval pipeline runs locally, without an LLM. Optional LLM calls belong to write-time curation and maintenance.
